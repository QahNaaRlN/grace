# Проверяемый импорт

Раздел `/imports` реализует принятую [SPEC-0017](specs/0017-persistent-import-drafts.md).
Доступ требует обычной сессии Grace. Данные каждого владельца изолированы.

1. Выберите JSON-снимок `grace.sheet-snapshot.v1` размером до 16 MiB,
   описанный в [инструкции подготовки снимка](import-review.md). Нужен исходный
   snapshot, а не `review.json`. Файл передаётся исходными байтами.
2. Нажмите «Сохранить черновик». Все листы, исходные ячейки и результат сверки
   сохраняются в приватной БД. Эта кнопка не создаёт финансовые операции.
   Повторная загрузка того же файла открывает тот же черновик.
3. Откройте строку, проверьте исходник и возможные совпадения. Выберите создание
   операции, связь с существующей, дубль другой строки или исключение.
   Укажите основание. Для новой операции выберите существующие счёт/категорию;
   исходные aliases не создают новые сущности. Если известен только день,
   явно уточните время с часовым поясом и основание уточнения.
4. Сохраните решение. Оно доступно после перезагрузки; история сохраняет
   автора, время и revision. Для продолжения откройте сохранённый черновик.
5. Выберите до 100 строк и нажмите «Предварительный просмотр». Проверьте
   новые операции, связи, исключения, предупреждения и изменения по счетам.
   Возможные совпадения требуют отдельного решения. Основную строку дубля
   включите в группу или подтвердите заранее.
6. Нажмите отдельную кнопку подтверждения. Сервер ещё раз проверит состояние
   и запишет всю группу атомарно. Повтор после потерянного ответа возвращает
   прежний результат. Истёкший или изменившийся preview требует новой проверки.

После подтверждения доступны результат и события со ссылками в журнал.
Связи, дубли и исключения не создают проводок. Остальные строки продолжают
жить как черновики. Подтверждённые решения и происхождение данных неизменяемы.

Поддерживаются покупка, полученный доход, погашение, перевод между своими
счетами и возврат существующей покупки. Планы, снимки задолженности/кредитных
карт, требования платежей и HOLD сохраняются как свидетельства. Заёмные
средства не превращаются в доход. Приватные документы по ссылкам не скачиваются.

Денежные расчёты выполняются сервером в int64 minor units. Web запрещает
передавать неточное JavaScript-число и подтверждать итог вне safe integer range;
для таких сумм нужен отдельный клиентский этап точного отображения.

Миграция 000007 сохраняет snapshot, решения, audit, preview, confirmation и
provenance. До публикации она может быть отменена. После любого подтверждения
rollback отказывает, чтобы сохранить свидетельства, даже если группа только
связывала/исключала строки. Backup должен включать всю БД.

Проверки на Linux: `make test`, `go vet ./...`, `make test-integration`.
На Windows через Git for Windows: `bash scripts/test-windows.sh unit` и
`bash scripts/test-windows.sh integration`. Адаптер сохраняет UTF-8 JSON,
пути контейнеров и размещает временный CLI-output вне Git checkout.
