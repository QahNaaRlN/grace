# Проверяемый импорт

Раздел `/imports` реализует принятую [SPEC-0017](specs/0017-persistent-import-drafts.md).
Доступ требует обычной сессии Grace. Данные каждого владельца изолированы.

## Перенос месяца — SPEC-0023

В ветке `codex/monthly-expense-migration` добавлен сценарий
[SPEC-0023](specs/0023-monthly-expense-migration.md). В основной версии и
production он пока не выпущен.

1. Сохраните копию «Финансового здоровья» на момент перехода. Для переноса
   операций экспортируйте **полный лист «Операции»** как CSV UTF-8. Сохраните
   первые четыре строки и порядок столбцов A:O; заголовки в строке 4:
   A начинается с «Дата», B с «Тип», F с «Сумма». Данные начинаются с строки 5.
   Разделитель — запятая или точка с запятой. Лишние столбцы отклоняются.
   Нельзя выгружать только диапазон старых итоговых формул: строки после 304
   тоже входят в историю. CSV хранит экспортированные значения; исходные
   формулы, заметки и другие листы доступны при загрузке полного JSON snapshot.
2. В разделе «Импорт» выберите CSV и стабильное название источника, затем
   сохраните черновик. Повтор тех же байтов открывает существующий batch;
   попытка назвать тот же файл другим источником отклоняется. Изменённый файл
   требует новой проверки совпадений. Оригинальные bytes сохраняются приватно.
3. Выберите нужный месяц. Отчёт охватывает все строки, независимо от страниц
   списка. «В таблице» — сумма исходных строк покупок с возможными дублями;
   «Подготовлено» — ещё не опубликованные решения; «Подтверждено» — уникальные
   подтверждённые покупки из строк месяца. Переводы и погашения не являются
   повторным потреблением. Каждая валюта считается отдельно; неизвестный итог
   не подменяется нулём.
4. Проверьте строки и счета оплаты. Начальный остаток счёта должен относиться
   к моменту **до** переносимых операций; импорт добавляет исторические проводки
   и не корректирует начальный остаток автоматически. Уже внесённую покупку
   нужно связать с исходной строкой, чтобы не создать второе списание.
   Возможные совпадения ищутся и внутри основного блока, и среди исправленных
   черновиков, и среди существующих событий. Они не сливаются автоматически.
5. Исправления суммы, даты, валюты и вида операции видны в отчёте; исходники
   сохраняются. Строки без даты остаются отдельными вопросами. Для отсутствующей
   даты владелец явно вводит время с основанием или выбирает существующее
   событие; только тогда строку можно отнести к месяцу. При известном только
   дне время не подставляется автоматически. Непроверенные строки остаются
   черновиками; исключения требуют причины.
6. Выбирайте до 100 строк, проверяйте preview и отдельно подтверждайте группу.
   При 191 строке нужны несколько групп. Выбранный месяц сохраняется после
   подтверждения; обновляются сверка, операции, счета и аналитика.
   Перенос завершён только когда все строки месяца подтверждены и нет
   нерешённых дат, которые могут относиться к нему. Повтор подтверждения
   не создаёт новые проводки.

Отчёт показывает происхождение расходов из этого batch, а не весь общий
оборот Grace. Покупка, явно перенесённая в другой месяц, видна как расхождение
и не входит в подтверждённый итог выбранного месяца.

## Общий процесс подтверждения

1. Выберите JSON-снимок `grace.sheet-snapshot.v1` размером до 16 MiB,
   описанный в [инструкции подготовки снимка](import-review.md). Нужен исходный
   snapshot, а не `review.json`. Файл передаётся исходными байтами.
2. Нажмите «Сохранить черновик». Все листы, исходные ячейки и результат сверки
   сохраняются в приватной БД. Эта кнопка не создаёт финансовые операции.
   Повторная загрузка того же файла открывает тот же черновик.
3. Откройте строку, проверьте исходник и возможные совпадения. Выберите создание
   операции, связь с существующей, дубль другой строки или исключение.
   Укажите основание. Для новой операции выберите существующие счёт/категорию;
   исходные aliases не создают новые сущности. Если известен только день,
   явно уточните время с часовым поясом и основание уточнения.
4. Сохраните решение. Оно доступно после перезагрузки; история сохраняет
   автора, время и revision. Для продолжения откройте сохранённый черновик.
5. Выберите до 100 строк и нажмите «Предварительный просмотр». Проверьте
   новые операции, связи, исключения, предупреждения и изменения по счетам.
   Возможные совпадения требуют отдельного решения. Основную строку дубля
   включите в группу или подтвердите заранее.
6. Нажмите отдельную кнопку подтверждения. Сервер ещё раз проверит состояние
   и запишет всю группу атомарно. Повтор после потерянного ответа возвращает
   прежний результат. Истёкший или изменившийся preview требует новой проверки.

После подтверждения доступны результат и карточки событий с постоянными ссылками.
Связи, дубли и исключения не создают проводок. Остальные строки продолжают
жить как черновики. Подтверждённые решения и происхождение данных неизменяемы.

Поддерживаются покупка, полученный доход, погашение, перевод между своими
счетами и возврат существующей покупки. Планы, снимки задолженности/кредитных
карт, требования платежей и HOLD сохраняются как свидетельства. Заёмные
средства не превращаются в доход. Приватные документы по ссылкам не скачиваются.

Денежные расчёты выполняются сервером в int64 minor units. Web запрещает
передавать неточное JavaScript-число и подтверждать итог вне safe integer range;
для таких сумм нужен отдельный клиентский этап точного отображения.

Миграция 000007 сохраняет snapshot, решения, audit, preview, confirmation и
provenance. До публикации она может быть отменена. После любого подтверждения
rollback отказывает, чтобы сохранить свидетельства, даже если группа только
связывала/исключала строки. Backup должен включать всю БД.

Проверки на Linux: `make test`, `go vet ./...`, `make test-integration`.
На Windows через Git for Windows: `bash scripts/test-windows.sh unit` и
`bash scripts/test-windows.sh integration`. Адаптер сохраняет UTF-8 JSON,
пути контейнеров и размещает временный CLI-output вне Git checkout.
