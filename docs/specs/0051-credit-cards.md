## Проблема и пользовательский результат

У владельца есть кредитные карты, кредиты с графиком, рассрочки и BNPL.
В Grace кредитная карта — это счёт типа `credit` с картами-инструментами
(SPEC-0040), но без условий: нет лимита, ставки, льготного периода и
минимального платежа. Погашение карты в Grace сейчас не ведётся: владелец
вносит его по-разному или не вносит. Операция «Погашение» (`debt_payment`)
списывает деньги со счёта оплаты, но долг кредитного счёта не уменьшает.

Результат: для каждой кредитной карты Grace показывает текущий долг,
доступный лимит, сколько и до какой даты заплатить, чтобы не платить
проценты, и минимальный платёж. Расчёт детерминированный, в Go, по введённым
владельцем условиям; неизвестное показывается как неизвестное.

## Scope

1. **Условия карты с версиями.** Для счёта типа `credit` — набор условий
   с датой начала действия. Новая версия не меняет прошлые расчёты.
   - кредитный лимит;
   - ставка на покупки и на снятие наличных (годовых, в базисных пунктах);
   - модель льготного периода (см. «Предметная модель»);
   - правило минимального платежа: процент от долга, минимальная сумма,
     добавляются ли начисленные проценты;
   - необязательный PDF условий в новой общей таблице документов
     (задел для импорта PDF на этапе 5) и примечание.
   Любое поле, кроме даты начала, может быть «неизвестно».
2. **Снимок долга из банка.** Владелец вводит то, что видит в приложении
   банка: дата, долг, доступный лимит, необязательно сумма для льготного
   периода и минимальный платёж с датой. Снимки хранятся историей.
3. **Долг по данным Grace.** Долг = отрицательный остаток кредитного счёта
   по проводкам (только если остаток сверен, SPEC-0040). Если есть снимок
   банка на ту же дату и суммы расходятся, Grace показывает расхождение
   и не выбирает «правильную» сумму сам.
4. **Погашение карты.** Действие «Погасить карту» создаёт перевод между
   своими счетами (`internal_transfer`) со счёта оплаты на кредитный счёт:
   деньги уходят с дебетового счёта, долг карты уменьшается, расходом это
   не считается. Новая операция-вид не вводится.
5. **Расчёты (Go, на дату):**
   - текущий расчётный период и дата его закрытия;
   - сумма и последняя дата платежа для сохранения льготного периода;
   - оценка минимального платежа и его дата;
   - доступный лимит = лимит − долг (если оба известны);
   - признак «льготный период под угрозой»: до даты меньше 3 дней и
     оплачено меньше нужной суммы.
6. **Напоминания** за 3 и 1 день до даты льготного и минимального платежа
   письмом, тем же механизмом, что у кредитов и подписок (SPEC-0034, 0046);
   включаются отдельно для каждой карты. Если нужная сумма уже оплачена,
   напоминание отменяется.
7. **Интерфейс.** На карточке кредитного счёта: блок «Условия» с
   историей версий, блок «Долг и лимит», блок «Льготный период» («Заплатите
   X ₽ до DD.MM, чтобы не платить проценты»), «Минимальный платёж», кнопки
   «Погасить карту» и «Ввести данные из банка». На главной — то же кратко
   для карт с ближайшей датой.

## Non-goals

- Кредиты с графиком: разделение платежа на тело и проценты, снимки остатка
  (следующая спецификация этапа 3).
- Рассрочки и BNPL (Сплит, Долями) — отдельная спецификация.
- Начисление процентов по дням и прогноз переплаты: Grace показывает дату,
  после которой начнутся проценты, но не считает их сумму.
- HOLD и неподтверждённые операции, сверка с выпиской PDF (этап 5).
- Извлечение условий из PDF через ИИ.
- Автоматическое преобразование прошлых `debt_payment` в переводы.
- Отдельный учёт снятия наличных и переводов с карты: в v1 все операции
  по карте считаются покупками (решение владельца).
- Перенос PDF кредитов из `loan_documents` в общую таблицу документов.
- Ввод истории долга до начала учёта.

## Текущее поведение и доказательства

- `accounts.type` ∈ `debit|credit|installment|cash` (миграция 000001);
  карты — `payment_instruments` счёта (000007), несколько карт на один счёт.
- Остаток = opening + credit − debit по `postings`, только при
  `balance_reconciled` (000011, SPEC-0040).
- `debt_payment` — одна проводка `debit` по счёту оплаты
  (`internal/financialevents/repository.go`, `resolveCommand`).
- Кредиты: `obligations` + `loan_details` + `loan_documents` + график
  (000005, 000018). Связи кредитного счёта с условиями нет.

## Предметная модель и инварианты

- **Договор = кредитный счёт.** Несколько карт одного договора — инструменты
  одного счёта, долг не дублируется.
- **Версии условий** `credit_card_terms(account_id, effective_from, …)`:
  уникальны по (счёт, дата). Для расчёта на дату D берётся версия с
  наибольшей `effective_from ≤ D`. Версию можно исправить (например,
  опечатку в ставке), но каждое изменение сохраняется ревизией с историей,
  как правки операций в SPEC-0041.
- **Модели льготного периода** (выбирает владелец):
  1. `statement` — расчётный период с днём выписки S и платёжный период
     P дней: покупки периода нужно погасить до S + P. Типичная «до 55 дней».
  2. `from_first_purchase` — N дней с первой покупки после полного
     погашения (типичные «120 дней»). Сумма для сохранения льготного
     периода = весь долг на дату окончания; промежуточные минимальные
     платежи — по правилу минимума.
  3. `none` — льготного периода нет.
  4. `unknown` — расчёт сроков не выполняется, показываются только долг
     и лимит.
- **Сумма для льготного периода** (`statement`): долг на дату закрытия
  последнего расчётного периода минус погашения после этой даты, не меньше 0.
  Покупки после закрытия переходят в следующий период.
- **Минимальный платёж:** max(процент × долг на дату выписки
  [+ проценты, если указано], минимальная сумма), не больше долга.
  Если правило неизвестно — «неизвестно», не ноль.
- **Снимок банка** никогда не меняет проводки. Расхождение — информация.
- **Деньги** — целые минимальные единицы, одна валюта счёта; расчёты по
  разным валютам не смешиваются.
- Заёмные деньги не являются доходом: покупка по кредитной карте —
  расход, погашение — перевод (не расход второй раз).

## API и OpenAPI

Новые операции (owner-scoped, CSRF/Origin как у остальных записей):

- `GET /api/v1/accounts/{id}/credit-card` — условия (текущая версия и
  история), последний снимок, расчёт на дату (`?on=YYYY-MM-DD`, по умолчанию
  сегодня в часовом поясе приложения).
- `POST /api/v1/accounts/{id}/credit-card/terms` — новая версия условий
  (Idempotency-Key). `PATCH …/terms/{version}` — правка с ревизией.
- `POST /api/v1/accounts/{id}/credit-card/snapshots` — снимок из банка.
- Погашение — существующий `POST /api/v1/financial-events/transfers`.

Схемы `CreditCardTerms`, `CreditCardSnapshot`, `CreditCardStatus`
(расчёт: `debtMinor`, `availableMinor`, `statementPeriod`, `graceAmountMinor`,
`graceDueOn`, `minimumMinor`, `minimumDueOn`, `graceAtRisk`, `unknown[]`).
Все суммы — строки минимальных единиц, как в остальном API.

## Ошибки и негативные сценарии

- Условия для счёта не типа `credit` → 422.
- `statement_day` вне 1–31: при коротком месяце выписка в последний день.
- Остаток счёта не сверен → долг Grace «неизвестен», расчёт идёт по
  последнему снимку банка, если он есть, с пометкой источника.
- Нет условий → блоки сроков показывают «Добавьте условия карты».
- Погашение больше долга → разрешено (переплата = положительный остаток
  кредитного счёта), с предупреждением в форме.
- Повтор запроса с тем же Idempotency-Key → тот же результат.

## Критерии приёмки

- [ ] AC1. Версии условий: расчёт на дату использует версию, действующую
  на эту дату; правка версии сохраняет историю ревизий.
- [ ] AC2. `statement`: для синтетических карт (выписка 5-го, 25 дней)
  сумма и дата льготного платежа совпадают с ручным расчётом в тестах,
  включая покупки до и после выписки, частичные погашения и короткий месяц.
- [ ] AC3. `from_first_purchase`: дата окончания считается от первой
  покупки после нулевого долга; полный долг — сумма для сохранения.
- [ ] AC4. Минимальный платёж по правилу (процент, минимум, проценты),
  не больше долга; неизвестное правило → «неизвестно».
- [ ] AC5. «Погасить карту» создаёт `internal_transfer`; долг карты
  уменьшается, расходы и доход за период не меняются.
- [ ] AC6. Снимок банка не меняет проводки; расхождение с долгом Grace
  показывается с обеими суммами.
- [ ] AC7. Несколько карт одного счёта не дублируют долг.
- [ ] AC8. Без условий и без сверенного остатка интерфейс показывает
  понятные состояния, а не нули.
- [ ] AC9. `make test`, `make test-integration`, `git diff --check`;
  OpenAPI и сгенерированные типы обновлены.

## Исполняемые проверки

- Go unit: расчёты периодов, льготной суммы, минимума (табличные тесты,
  синтетические карты, границы месяцев и високосный год).
- Интеграция PostgreSQL: версии, снимки, RLS, погашение переводом.
- Web: хуки мутаций по SPEC-0048 с инвалидацией счетов, событий и
  денежной позиции; компонент блока карты в состояниях «нет условий»,
  «не сверено», «под угрозой».
