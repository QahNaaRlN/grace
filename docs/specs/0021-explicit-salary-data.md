# SPEC-0021: не выводить зарплату из общего типа дохода

- Статус: integrated
- Автор: Codex
- Дата: 2026-10-06
- Acceptance owner: владелец Grace
- Acceptance record: исходное принятие макета SPEC-0020 и поручение продолжить его реализацию; исправление обеспечивает уже принятый инвариант «неизвестные данные не подменяются предположениями» без расширения продукта.
- Implementation branch: codex/home-design-audit

## Проблема и результат

FinancialHealth показывал любой income_received в разделе «Зарплата».
Этот enum определяет направление и смысл дохода, но не его принадлежность
к зарплате. Доход от аренды или возврата долга не должен классифицироваться
как зарплата клиентом.

## Scope / non-goals

Удалить этот вывод из React. Общие доходы сохраняются в операциях/аналитике;
зарплатные колонки остаются неизвестными до появления явной модели/связи.
Не менять записи, API, миграции, расчёты, категории или маршрутизацию ассистента.

## Текущее поведение / модель / API / rollback

Сервер не предоставляет salary/payment-component discriminator.
Неизвестное остаётся неизвестным. API и база не меняются. Rollback приложения
не требует database migration; возврат ошибочной классификации не рекомендован.

## Ошибки и негативные сценарии

Пустой набор и произвольный доход одинаково не создают зарплатную запись.
Существующая income_received остаётся доступна в разделе операций.

## Критерии и исполняемые проверки

- AC1: произвольный income_received не появляется как зарплата; Web regression test.
- AC2: операция дохода видна в операциях FinancialHealth, её данные не потеряны; тот же test.
- AC3: make test, git diff --check, CI, Delivery и deployment проходят до handoff.

## Открытые решения

Нет. Явная зарплатная модель остаётся отдельным этапом.
