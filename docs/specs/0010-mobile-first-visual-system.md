## Проблема и пользовательский результат

Web уже функционален, но визуальная иерархия слаба, интерфейс воспринимается как
набор технических форм, а интерактивные элементы не всегда выглядят
интерактивными. Основной пользовательский экран — телефон, поэтому desktop-first
плотность и навигация не могут быть исходной точкой.

Пользователь получает спокойный, единообразный финансовый интерфейс, в котором
главные суммы и состояния читаются с первого экрана, навигация доступна большим
пальцем, а формы и списки не требуют горизонтальной прокрутки.

## Scope

- закрепить shadcn/ui `radix-nova` как базовую компонентную систему Web;
- обновить design tokens, фон, поверхности, типографическую иерархию и focus states;
- сделать mobile-first shell с нижней навигацией и desktop-навигацией в header;
- обеспечить `cursor: pointer` для доступных интерактивных элементов и
  `not-allowed` для disabled controls;
- поднять основные touch targets до минимальных 44 CSS px;
- улучшить визуальную иерархию финансовой картины и ассистента;
- заменить вводящую в заблуждение надпись `API недоступен` на состояние загрузки
  данных конкретного экрана;
- проверить layout на ширинах 390 px и desktop без горизонтального overflow.

## Non-goals

- изменение API, финансовых правил, PostgreSQL или OpenAPI;
- новые финансовые возможности, графики или AI-возможности;
- dark theme toggle;
- отдельное нативное приложение;
- замена shadcn/ui другой библиотекой или добавление второй дизайн-системы.

## Текущее поведение и доказательства

- `web/components.json` уже фиксирует shadcn/ui со стилем `radix-nova`, Radix UI,
  Tailwind CSS и Lucide;
- базовая кнопка имеет высоту 32 px и не задаёт pointer cursor;
- навигация находится только в верхнем header;
- `HomePage` показывает `API недоступен` при ошибке любого одного query;
- формы адаптивны частично, но действия и плотность оптимизированы скорее под
  desktop.

полученные от deterministic financial core. Presentation не вычисляет новое
финансовое состояние и не переносит бизнес-правила в React.

## API и OpenAPI

Без изменений.

Без изменений. Rollback — возврат UI-коммита; данные и API совместимы.

## UI

- Базовая библиотека: shadcn/ui `radix-nova` с Radix primitives, Tailwind CSS и
  Lucide icons.
- Mobile-first означает, что базовые классы описывают телефон, а `sm`/`md`/`lg`
  только расширяют layout.
- Минимальная цель для primary controls — 44x44 CSS px.
- На телефоне основные разделы доступны через fixed bottom navigation с учётом
  safe-area; на desktop навигация остаётся в header.
- Цвет используется для статуса и иерархии, но не является единственным носителем
  смысла.
- Focus-visible остаётся отчётливым, disabled элементы не обещают действие.

## Ошибки и негативные сценарии

- Ошибка одного query не должна утверждать, что весь API недоступен.
- Длинные суммы, названия и badges не должны создавать горизонтальный scroll.
- Bottom navigation не должна перекрывать последний контент.
- При отключённом ассистенте финансовый экран остаётся полностью рабочим.

## Критерии приёмки

- [x] Библиотека и mobile-first принцип зафиксированы в документации.
- [x] Все доступные buttons/links/select items показывают pointer cursor.
- [x] Основные inputs, selects и buttons имеют touch target не меньше 44 px.
- [x] На 390 px нет горизонтального overflow и доступны оба раздела навигации.
- [x] На desktop сохраняется ясная двухколоночная композиция там, где она полезна.
- [x] Финансовая картина и ассистент имеют согласованную визуальную систему.
- [x] Ошибки загрузки описывают данные экрана, а не объявляют весь API мёртвым.
- [x] API, OpenAPI и финансовая модель не изменены.
