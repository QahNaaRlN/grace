| AC3 | Решение 1(а): разница у сверенного счёта → операция `balance_adjustment` на момент сверки; в доходы, расходы, возвраты и итоги дня не входит; её сумму нельзя изменить, а саму её — отменить (связь «сверка остатка») | Интеграция: разница −100 ₽ → баланс равен банковскому, `PeriodSummary` без изменений, отмена корректировки → `LinkError{"сверка остатка"}`, история из 2 сверок |

| AC5 | RLS, append-only (только SELECT/INSERT), `Idempotency-Key`, `previewHash` | Интеграция: UPDATE и DELETE сверок запрещены ролью приложения; повтор ключа возвращает ту же сверку; операция между предпросмотром и подтверждением → `ErrStalePreview`; чужой владелец: предпросмотр → `ErrNotFound`, история пуста, правка запрещена. UI: устаревший предпросмотр показывает объяснение и снова предлагает «Проверить» |

Проверки: `make test-integration` (все пакеты, exit 0); `make test` — Go `ok`, web 189 тестов,
lint, build; `git diff --check` — чисто.

Решения и отклонения:
- Решение 4: операции «без времени» в день сверки входят в остаток на момент (проверено тестом).
- Решение 3: архивирование счёта не входит в этап.
- У счёта нет поля «банк»: банк хранится у карты, поэтому редактируется в карте.
- Отдельный `scripts/test-account-reconciliation.sh` не создан: `./internal/accounts` добавлен в
  `scripts/test-ux-refinement.sh` и входит в `make test-integration`.
- Из шторки убраны пустые «Кредитные условия и выписка» (все поля были «Не указано»): данных
  за ними нет; шторка показывает только заполненные сведения, как карточка операции SPEC-0043.
- Миграция 21: значение enum `balance_adjustment` добавляется с `IF NOT EXISTS`, потому что
  PostgreSQL не умеет удалять значения enum при откате; откат отказывается выполняться, если
  есть сверки или отключённые карты.
