# SPEC-0055 / S1.6: один новый прогон с диагностикой S1.5

- Дата: 2026-10-21, Asia/Yekaterinburg.
- Статус: draft; implementation_status: not_started.
- Основание: владелец слил [PR №78](https://github.com/QahNaaRlN/grace/pull/78),
  коммит `29a28a71d6e7d895c95e707f831dc59622ff25c8`; [S1.5](0055-s15-screening-diagnostics.md)
  включена в main. Это не разрешение нового платного запуска.
- Граница решения: реализация отдельного разрешения запуска и ровно один smoke;
  без развёртывания приложения, переключения модели в продукте и активации по PASS.

## Результат

Проверить Gemini 3.1 Flash Lite / Google EU на прежних трёх публичных
синтетических PDF, используя report v2 и безопасную диагностику S1.5. Новый
результат хранится отдельно; исходный FAIL S1.4 и его сверка расхода неизменяемы.
Новый запуск может показать текущую причину отказа, но не восстанавливает
утраченный HTTP-ответ прежнего запуска и не доказывает его историческую причину.

## Точный профиль и расходы

- Только `google/gemini-3.1-flash-lite` / `google-vertex/eu`, имя `Google`.
  Canonical slug, другая модель или маршрут автоматически не допускаются.
- До inference — свежие официальные metadata точного endpoint и список ZDR;
  прежние проверки статуса, параметров, лимитов и цен. Несовпадение — отказ до
  reservation/inference, без выбора замены и повышения пределов.
- До 100000 входных / 16000 выходных токенов на документ. Ценовые пределы:
  275000 / 1650000 USD micros за миллион токенов; до 53900 micros на вызов.
- Ровно один запуск, максимум 3 вызова, общий provider cap **161700 micros
  ($0.1617)**. Прежний общий бюджет и fees сохраняются; его остаток не сбрасывать.
  Существующий ledger должен разрешать всю reservation, иначе отказ до inference.
- Порядок: columns → cards → turnover-roles-ru. Первая ошибка останавливает запуск.
  Неиспользованные вызовы не переносятся; автоматических повторов, исправления
  ответов или fallback нет. До 420 секунд на запуск / 120 секунд на вызов.

## Исполнение

1. Отдельное фиксированное разрешение `s16-gemini31-diag-20261021`, отдельные
   private report/marker на VPS. Старые пути `s14-gemini31-20261020` не изменять,
   не удалять и не использовать для S1.6. Оба разрешения защищены от повторов,
   включая другой SHA или повторное выполнение workflow.
2. Явный отдельный режим существующего workflow, по умолчанию выключен.
   Проверить взаимоисключение с deploy, прежним S1.4, inspection и settlement;
   единая очередь production и существующая эксклюзивная блокировка.
3. Зафиксировать новый полный SHA после реализации. До запуска все jobs CI этого
   SHA должны пройти. Собрать операторский binary и проверить manifest/hashes
   трёх прежних PDF. Ключ и подключение к БД остаются на сервере; пользовательские
   документы, их текст и личные drafts в smoke не используются.
4. Сначала read-only preflight; marker расходуется непосредственно перед run.
   Whole-run reservation/settlement — прежние функции. Подтверждённый расход
   учитывается точно; неизвестный оставляет uncertain и запрещает дальнейшие
   платные вызовы. Никакого нулевого settlement по догадке. Unverified correlation
   из S1.5 не является подтверждённым billing и не разрешает автосверку.
5. Отчёт `statement.screening.v2.gemini31-diagnostics` сохраняет проверенные calls,
   результаты, fixed diagnostic и приватный correlation при отказе. Public summary
   содержит только разрешённые коды/счётчики/флаги. Приватные отчёты — 0600;
   временные binary/PDF удаляются, report и marker сохраняются.
6. Application container/image, config, флаги, финансовые записи и drafts не
   меняются. Проверить идентичность image/container и health до/после run.
   Успех всех трёх cases не меняет production policy и не является full corpus
   qualification. Для модели в продукте потребуется отдельное решение.

## Критерии приёмки

| ID | Исполняемое подтверждение |
| --- | --- |
| N1 | Операторские заглушки: preflight fail без marker/inference; failed/successful run оставляет новый marker; повтор и другой SHA не вызывают модель; старый marker/report сохраняются |
| N2 | Взаимоисключение режимов workflow; отсутствие inference по умолчанию; SHA/CI/manifest и прежние PDF hashes проверяются до оплачиваемого вызова |
| N3 | Прежние scorer и guards: fake-provider columns19/19, cards20/20, RU23/23, негативные случаи FAIL; D1–D4 S1.5 сохраняются |
| N4 | make test, затронутые интеграционные проверки и deployment mocks, git diff --check; до единственного отдельно утверждённого run external inference=0 |
| N5 | Один live run: либо полный PASS 19/20/23, либо честный FAIL с безопасным кодом и неизвестными границами; приватный отчёт и metering сохранены, image/health не менялись, повторов и активации нет |

При отсутствии достаточного остатка бюджета, изменении metadata/цен или
неизвестном billing запуск останавливается. Контракт не разрешает обход этих
условий, новые платные кампании, management key, изменение retention либо
дальнейшее расширение корпуса.
