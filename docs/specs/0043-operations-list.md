## Проблема и пользовательский результат

На «Операции» каждая операция — крупная карточка с бейджем вида, раскрытием
«Все сведения операции» и десятком полей «Не указано»; сканировать список
трудно. Результат: компактный список по дням, где с первого взгляда видно
категорию (иконка), продавца/описание, счёт и сумму, а подробности и
действия — в шторке операции.

## Scope

1. **Строка операции** (одна строка, ≥ 56px): иконка категории (SPEC-0042;
   для доходов/переводов/погашений — иконка вида), продавец или описание,
   под ним «категория · счёт» мелко, справа `Money` со знаком. Перевод —
   одной строкой «Счёт A → Счёт B».
2. **Группировка по дням** с заголовком «13 октября, понедельник» и итогом дня
   (расход/приход, считает Go); «время неизвестно» — отдельная пометка в строке.
3. **Шторка операции** по нажатию: сумма, вид, дата и время, счёт/карта,
   категория, описание, продавец, чек (если есть), связь с обязательством/
   подпиской, источник (ручной ввод / импорт со ссылкой на строку);
   поля «Не указано» не показываются списком — только заполненные.
   Действия: изменить/отменить (SPEC-0041), «Добавить состав» (чек).
4. **Фильтры** в одну строку: период, категория, счёт, вид, поиск по
   описанию/продавцу; количество найденных; пагинация курсором
   («Показать ещё»), не «до 100 последних».
5. **Сайдбар:** аватар профиля (или первая буква имени на `secondary`)
   и отображаемое имя внизу, ссылка на «Профиль и доступ»; на телефоне —
   аватар в кнопке «Меню» (уже есть) и в шапке меню.

## Non-goals

- Редактирование операций — SPEC-0041; иконки — SPEC-0042.
- Выгрузка операций в файл.

## Предметная модель и инварианты

- Итоги дня и количество считает Go (поля в ответе списка), не React.
- Порядок: дата операции (date-only — в конце дня), затем время создания.

## API и OpenAPI

`GET /api/v1/financial-events?cursor&limit≤100&from&to&categoryId&accountId&kind&q`
→ `{items, nextCursor, dayTotals[{date, currency, inflowMinor, outflowMinor}]}`.

## Данные, миграция и rollback

Индекс для поиска (`lower(merchant)`, `lower(description)`) — миграция без
изменения данных; rollback удаляет индекс.

## UI

См. Scope; 320px — строка в два уровня, сумма справа; клавиатура: строки —
кнопки, шторка — Dialog с возвратом фокуса.

## Ошибки и негативные сценарии

Нет операций за период; операция без категории (доход); 10 000 операций —
пагинация; длинные названия; разные валюты в одном дне.
