## Проблема и пользовательский результат

Владелец накопил месяц расходов в таблице «Финансовое здоровье». Переход
на Grace должен сохранять историю без ручного повторного ввода каждой суммы.
Каждая исходная строка должна остаться доступной, а итог выбранного месяца —
проверяемым до и после подтверждения. Наличие дублей, пропусков или ошибок
не должно превращаться в сообщение «перенос завершён».

## Scope

- Использовать accepted SPEC-0017 и её существующую реализацию как основу
  сохраняемых черновиков, аудита, сопоставления, preview и атомарной публикации.
  Совместить её с текущими входом, дизайном и миграциями main в этой ветке.
- Сохранить загрузку полного JSON snapshot v1 и добавить загрузку CSV листа
  «Операции», экспортированного целиком: данные с строки 5, столбцы A:O.
  CSV UTF-8, необязательный BOM, разделитель запятая или точка с запятой;
  A4 начинается с «Дата», B4 с «Тип», F4 с «Сумма». Неизвестная структура
  отклоняется, значения сохраняются как текст без вычисления формул.
- Добавить серверный отчёт сверки одного календарного месяца для всего batch,
  независимо от страницы списка. Отчёт показывает все строки месяца,
  непроверенные/подготовленные/подтверждённые решения, суммы расходов по
  валютам, дубли, исключения с причинами, изменения суммы/даты/вида операции.
- Строки без корректной даты учитываются отдельным списком и блокируют
  вывод о полноте месяца, пока владелец явно не уточнит дату с основанием
  либо не свяжет строку с существующим событием или не подтвердит исключение
  с причиной. Исходная неизвестная дата
  остаётся видимой; даты иных месяцев видны в количестве вне периода.
- UI выбора месяца, сверки и перехода к исходной строке; отчёт обновляется
  после сохранения решения и подтверждения. Завершённость означает подтверждение
  всех строк месяца и отсутствие нерешённых дат. Подтверждённое исключение
  с причиной не требует назначения месяцу; исходник остаётся в отдельном списке.

В scope также входит проверка возможных дублей по календарной дате/сумме/виду
среди всех строк batch, включая основной блок до строки 304 и исправленные
черновики. Совпадение требует явного решения; одинаковые суммы не сливаются.

## Non-goals

Прямая синхронизация Google, XLSX, OCR/PDF, LLM, автоматическое слияние,
публикация реальных данных агентом, deployment, перенос долговых снимков и
планов, изменение opening balance или условий кредитов. CSV содержит только
экспортируемые значения; для формул и остальных листов нужен JSON snapshot.
Новый финансовый тип date-only не вводится: исходная точность остаётся в
provenance, время создания события владелец уточняет явно по SPEC-0017.

## Текущее поведение и доказательства

Main 2c21983 содержит SPEC-0016 и офлайн-профиль «Операции» A:O,
данные с строки 5, дополнительный блок после строки 304. Реализация
SPEC-0017 существует в codex/persistent-import-drafts (034dd22), но ещё
не интегрирована. Её миграция 000007 конфликтует с payment instruments main:
перенумеровать только новую миграцию импорта в 000009. Общего месячного
отчёта и доступной пользователю CSV-загрузки пока нет.

## Предметная модель и инварианты

1. Нормализацию и суммы рассчитывает Go. Положительные деньги — int64 minor
   units, валюты раздельны, overflow и неизвестные суммы не подменяются нулём.
2. Месяц задаётся YYYY-MM, календарь Asia/Yekaterinburg. Исходная local date
   определяет принадлежность строки месяцу; уточнённая дата события показывается
   отдельно, выход в другой месяц считается расхождением.
   При отсутствующей/ошибочной исходной дате принадлежность определяется только
   явно уточнённой датой create с reason/timeReason или выбранного link с reason.
3. Исходный итог расходов — сумма всех исходных purchase строк месяца.
   Это сумма строк, которая может включать дубли, а не подтверждённое потребление.
   Неизвестная сумма делает соответствующий итог неизвестным.
4. Целевой итог — сумма уникальных purchase create/link_existing событий
   после решений. duplicate_of и exclude не добавляют потребление; ссылки
   на одно событие считаются один раз. Prepared и confirmed итоги разделены.
   Для link используется фактическая сумма/дата существующего события.
5. Каждая строка имеет координаты, исходные поля, действие, признак публикации,
   причину, исходную и целевую сумму/дату/вид, объяснение изменения. Строка
   без суммы/даты, неподтверждённая строка и неподдерживаемое решение видимы.
6. Отчёт не является разрешением публикации. Проверки кандидатов, финансовых
   ссылок, preview hash/revision, CSRF/Origin, RLS и идемпотентности SPEC-0017
   обязательны. Загрузка/отчёт/сохранение решений не меняют postings.
7. CSV хранится исходными байтами в приватном batch snapshot; raw cells отчёта
   сохраняют строки и координаты. Source ID пользователь задаёт явно;
   capturedAt не участвует в идентичности исходных байтов. Повтор тех же bytes
   для того же owner возвращает batch; другой sourceId при тех же bytes — conflict.
8. Заголовки и пустые строки не являются операциями, но непустые строки A:O
   с ошибками сохраняются для review. Лимиты SPEC-0016 соблюдаются, максимум
   15 CSV колонок; остаток колонок не отбрасывается молча.

## API и OpenAPI

- POST `/api/imports/csv?sourceId=...`: body text/csv, UTF-8, до 16 MiB;
  Idempotency-Key, session, CSRF, Origin. 201/200 batch; 400 invalid_csv,
  409 source_conflict, 413 body_too_large. Сервер создаёт профиль snapshot
  и использует общий pipeline SPEC-0017.
- GET `/api/imports/batches/{batchId}/month?month=YYYY-MM`: read-only
  owner report с batchRevision, timezone, complete, counts, currency totals,
  строками месяца и строками с неизвестной датой. Чужой batch — 404;
  отсутствующий/некорректный месяц — 400 invalid_month.
- DTO только из api/openapi.yaml; TypeScript regenerate.

## Данные, миграция и rollback

Новых таблиц сверх SPEC-0017 не требуется. CSV bytes сохраняются в bytea
snapshot, нормализованный report — в существующем поле report. Новая схема
импорта имеет номер 000009, существующие 000007/000008 не меняются.
Rollback защищает опубликованные import events по SPEC-0017. Отключение
месячного отчёта и CSV routes сохраняет операции, исходники и provenance.

## UI

Раздел «Импорт» доступен из дополнительного меню актуального mobile-first
layout. Выбор JSON/CSV файла; для CSV явное имя источника и инструкция
экспорта полного листа «Операции». Выбор месяца type=month, серверные итоги
и статус полноты, отдельные неподтверждённые/неизвестные строки. Переход
к строке открывает существующее редактирование. Денежные значения сверх
безопасного диапазона JS не показываются как точные. Подтверждение по
прежнему отдельная кнопка после preview, до 100 строк на группу.

## Ошибки и негативные сценарии

Повреждённый CSV, неверная кодировка/структура, лишние колонки и превышение
лимитов отклоняются до записи. Неоднозначные денежные значения остаются
issues, не исчезают. Разные валюты не складываются. Неразрешённые дубли
блокирует preview. Отчёт не делает batch completed из-за одного месяца.
После ошибки/session expiry сохранённый черновик доступен для продолжения.
Реальные исходники не попадают в fixtures, Git или логи.

## Критерии приёмки

- [x] AC1: CSV экспорт сохраняет все непустые строки, включая >304 и текстовые
  суммы; BOM, quoted separators/newlines, пустые строки и malformed проверены.
- [x] AC2: Месячный отчёт охватывает >100 строк независимо от pagination;
  неизвестные даты и неполные суммы видимы, арифметика точная по валютам.
- [x] AC3: create/link/duplicate/exclude дают объяснимые итоги; повторная
  ссылка не удваивает сумму; правки суммы/даты/вида видимы; полный отчёт
  возможен только после подтверждения всех строк и разрешения неизвестных дат
  либо явного подтверждённого исключения с причиной.
- [x] AC4: Загрузка/review/report не пишут ledger; confirmation сохраняет
  историческую дату, provenance и идемпотентность, расходы видны в аналитике.
- [x] AC5: RLS/session/CSRF/Origin защищают CSV и отчёт; чужой batch даёт 404;
  миграция совместима с main и rollback после публикации запрещён.
- [x] AC6: Мобильный UI поддерживает CSV/JSON, выбор месяца, серверные итоги,
  resume и отдельное подтверждение. Контракт и типы согласованы.
- [x] AC7: make test, go vet ./..., import integration и git diff --check
  проходят; evidence перечисляет критерии, исполняемые проверки и ограничения.

## Открытые решения

Scope принят прямым поручением создать эту спецификацию и реализовать
обсуждённый перенос. Время неизвестных date-only операций уточняется владельцем;
перенос не требует придумывания времени агентом. Пользователь подтверждает
реальный импорт самостоятельно после выпуска; этот work item предоставляет
проверяемую реализацию на синтетических данных.
