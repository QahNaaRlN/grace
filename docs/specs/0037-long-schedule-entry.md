## Проблема и пользовательский результат

Ипотека — 120–360 платежей, рассрочка — 12–24, но форма принимает график
только построчно: «Добавить платёж», дата, сумма, повторить. Дополнительно
нужно вручную ввести «Общую сумму», которая обязана совпасть с суммой строк
до копейки (`handler.go: sum == request.TotalMinor`). Результат: график на
120 платежей вводится за минуту — шаблоном равных платежей или вставкой из
таблицы банка — и проверяется глазами до сохранения.

## Scope

1. Три способа заполнить график в «Новое обязательство» и в черновике графика
   кредита (SPEC-0034, `LoanPanel`):
   - **Равные платежи**: дата первого платежа, количество (1–600),
     периодичность (ежемесячно; еженедельно — открытое решение), сумма
     платежа, необязательные отдельные суммы первого и последнего платежа.
     Даты считает Go (`internal/commitments/calendar.go`, anchor day,
     конец месяца — последний день), Asia/Yekaterinburg.
   - **Вставить из таблицы**: многострочный текст из выписки/PDF/Excel банка;
     каждая строка — дата (`ДД.ММ.ГГГГ`, `ГГГГ-ММ-ДД`) и сумма
     (`20 000,00`, `20000.00`, `20 000 ₽`); разделители — таб, `;`, пробелы;
     лишние колонки (основной долг, проценты, остаток) допускаются, если
     указано, какая колонка — платёж. Ошибочные строки показываются с
     номером и причиной, остальные не теряются.
   - **Вручную**: компактная таблица (дата | сумма | удалить) вместо карточки
     на строку; Enter в последней сумме добавляет строку с датой +1 месяц
     (дату считает Go через тот же preview); «Заполнить сумму вниз».
2. Сводка над таблицей: число платежей, первая и последняя дата, итог (от Go).
   Поле «Общая сумма» удаляется из ввода: итог = сумма графика, показывается
   только для чтения.
3. Длинный график свёрнут: первые 3 и последние 3 строки + «Показать все N»;
   правка любой строки остаётся доступной.

## Предметная модель и инварианты

- Генерация и разбор — детерминированный Go (новый
  `internal/obligations/schedulepreview.go`), без записи в БД.
- Равные платежи: `amountMinor × (count − специальные) + first + last`;
  переполнение int64 → ошибка; даты строго возрастают.
- Разбор вставки: суммы через тот же парсер minor units, что и API
  (без float); даты — только реальные календарные; дубли дат — ошибка строки.
- Создание обязательства по-прежнему проходит `POST /api/v1/obligations`
  с явными строками: preview ничего не сохраняет, пользователь видит
  итог и подтверждает сохранение.

## API и OpenAPI

Новый `POST /api/v1/obligations/schedule-preview` (session + CSRF, без
идемпотентности — не пишет):

    request: oneOf
      { mode: "equal", firstDueOn: date, count: 1..600,
        interval: "monthly", amountMinor: int64>0,
        firstAmountMinor?: int64>0, lastAmountMinor?: int64>0 }
      { mode: "paste", text: string ≤ 64 KiB, amountColumn?: 1..12 }
      { mode: "rows", payments: [{ dueOn, amountMinor }] ≤ 600 }
        — добавлено при реализации: проверка и итог отредактированных строк
          (AC4), чтобы сумму считал Go, а не React
    response 200:
      { payments: CreateScheduledPayment[] (≤600), totalMinor: int64,
        firstDueOn: date, lastDueOn: date,
        rejectedLines: [{ line: int, text: string, reason: string }] }
    400: невалидный запрос; 422: ни одной валидной строки.

После изменения контракта — `npm run generate:api`.

переходит в список «дата — сумма».

## Ошибки и негативные сценарии

count 0/601; первая дата в прошлом (разрешено, отмечается «уже прошло»);
31 января + ежемесячно → 28/29 февраля, 31 марта; вставка 400 строк с
заголовком и итоговой строкой «Итого» (заголовок и «Итого» отклоняются с
причиной, не ломают разбор); смешанные `,`/`.`; неубывающие даты; NBSP;
пустая вставка; 64 KiB + 1 байт; одновременная правка черновика кредита
(SPEC-0034 revision) — preview не обходит проверку revision.
