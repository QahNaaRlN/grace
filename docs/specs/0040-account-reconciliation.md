## Проблема и пользовательский результат

На «Счета и карты» все 10 счетов «Не сверён», а диалог счёта только
показывает сведения: нельзя сверить остаток, исправить название, банк,
номер или карту, нельзя увидеть, когда данные последний раз обновлялись.
SPEC-0028 сознательно отложила перевод счёта в «сверен» до отдельной
процедуры. Результат: человек открывает счёт, видит последнюю сверку и
последний импорт, исправляет сведения и сверяет остаток с банком.

## Scope

1. **Сведения счёта редактируются:** название, тип нельзя менять после
   появления операций (смена debit↔credit меняет смысл баланса), банк;
   платёжные инструменты: добавить карту, изменить название/банк/последние
   4 цифры, отключить карту (история её операций сохраняется).
2. **Сверка остатка** — отдельное подтверждаемое действие: человек вводит
   фактический остаток из банка и момент (дата и время, Asia/Yekaterinburg);
   Go вычисляет остаток Grace на этот момент и разницу.
   - Разница 0 → счёт сверен на этот момент.
   - Несверенный счёт (SPEC-0028) без начального остатка: Go выводит
     начальный остаток = фактический − (поступления − списания до момента)
     и показывает его на подтверждение; после подтверждения счёт сверен.
   - Разница ≠ 0 у сверенного счёта → см. открытое решение 1.
   Каждая сверка сохраняется (кто, когда, на какой момент, введённый и
   вычисленный остаток, разница, решение) и не удаляется.
3. **«Последняя синхронизация»** в карточке и диалоге счёта: последняя
   сверка (момент и результат) и последний подтверждённый импорт по счёту
   (дата и время). В Grace нет подключения к банку, поэтому
   «синхронизация» = сверка или импорт; слово используется только с этим
   пояснением.
4. Диалог счёта становится страницей/шторкой счёта: сведения, карты,
   сверки (история), последние операции по счёту.

## Предметная модель и инварианты

- `AccountReconciliation{id, account_id, owner_id, as_of TIMESTAMPTZ,
  stated_minor, computed_minor, difference_minor, outcome, created_at}` —
  append-only, owner RLS.
- Остаток Grace на момент = opening + credits − debits по проводкам с
  `occurred_at ≤ as_of`; date-only операции дня `as_of` — открытое решение 4.
- Вывод начального остатка разрешён только для `balance_reconciled = false`
  и только при подтверждении; после — `balance_reconciled = true`.
- Сверка не создаёт и не меняет операций, кроме случая решения 1(а).
- Деньги — integer minor units + валюта счёта.

## API и OpenAPI

- `PATCH /api/v1/accounts/{id}` — сведения (revision для конкурентных правок).
- `POST/PATCH /api/v1/accounts/{id}/payment-instruments[/{cardId}]`.
- `POST /api/v1/accounts/{id}/reconciliations/preview` → вычисленный
  остаток, разница, предлагаемый начальный остаток; ничего не пишет.
- `POST /api/v1/accounts/{id}/reconciliations` (Idempotency-Key, previewHash)
  → запись сверки.
- `GET /api/v1/accounts/{id}/reconciliations`; в `Account` — `lastReconciliation`
  и `lastImportConfirmedAt`.

## Данные, миграция и rollback

Миграция: таблица сверок, `payment_instruments.disabled_at`, `accounts.revision`.
DOWN отказывается удалять существующие сверки (как миграция 18).

## UI

Строка счёта: название, «Сверен 13 окт., 14:20» / «Не сверён · импорт 9 окт.»
(`StatusBadge`), остаток через `Money`. Шторка счёта: «Сверить остаток»
(MoneyInput + дата/время → предпросмотр разницы → подтверждение),
«Изменить сведения», карты, история сверок.

## Ошибки и негативные сценарии

Момент в будущем; момент раньше первой операции; конкурентная правка
(revision); повтор подтверждения (idempotency); устаревший preview;
кредитный счёт (отрицательный остаток); счёт другой валюты.

## Критерии приёмки

- [x] AC1: сведения счёта и карты редактируются; тип заблокирован при наличии операций.
- [x] AC2: сверка несверенного счёта выводит начальный остаток, после

  с датой и временем.

## Открытые решения

1. Разница у сверенного счёта: (а) создать операцию «Корректировка остатка»
   (новый вид события, не расход и не доход в статистике) или (б) только
   зафиксировать расхождение и показывать его до следующей сверки.
2. Нужна ли сверка «на конец дня» (только дата) вместо даты и времени.
3. Архивирование счёта без операций/с операциями.
4. Date-only операции в день сверки: включать в остаток на момент или нет.
