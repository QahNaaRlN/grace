## Проблема и пользовательский результат

Принятый макет главной страницы переносится из демонстрации в React с реальными
данными: обзор → платежи → последние операции → счета. Пользователь может
создать первый счёт, проверить операцию перед сохранением и начать smoke-тест
опубликованной версии. Основание: home-ux-audit.md и home-redesign-prototype.md.

## Scope и UI

Палитра индиго в светлой/тёмной теме; единые Lucide-иконки, типографика,
перенос длинных сумм; padding hover/focus списков и селектов; 24px перед
действиями и 12px между ними; cursor pointer только у интерактивных элементов.
Маршруты /, /operations, /payments, /accounts, /analytics, /health, /profile;
основная навигация обзор/операции/платежи и дополнительное меню, доступный
Radix dialog, нижняя мобильная панель с safe-area. Ассистент и существующие
чеки/обязательства/settlements сохраняются. Формы открываются по действию,
операция сохраняется только после подтверждения. Первый счёт создаётся через
существующий защищённый accounts API. Данные не заменяются демонстрационными.

Название, банк и последние четыре цифры карты сохраняются отдельно в
payment_instruments, связанном со счётом. Отображение использует полный
идентификатор, связи — UUID; ведущие нули сохраняются. Несколько инструментов
не дублируют баланс. Наличные не требуют банка/номера.

## Non-goals и совместимость с таблицей

Сохраняется формат доступных сведений таблицы «Финансовое здоровье» и все
колонки в деталях. Отсутствующие в модели значения обозначаются неизвестными;
нет фиктивного заполнения, форм редактирования неподдерживаемых кредитных
условий, вычисления grace или финансовых правил в React. Новая кредитная
модель, бюджетные лимиты, план зарплаты, OCR и десять CRUD-подсистем не входят
в визуальную переработку. Исходные импортируемые поля сохраняются по SPEC-0016;
публикация черновиков импорта остаётся в отдельной SPEC-0017/PR 7.

## Текущее поведение

Большая hero-секция, все формы и полный журнал постоянно на главной; две
кнопки мобильной навигации. Ошибка analytics не включена в индикатор актуальности.
Первого счёта через Web создать нельзя. Card имеет зелёный gradient; CSS
объявляет незагруженный Inter. Account API не содержит карточных реквизитов.

## Предметная модель и инварианты

Деньги — integer minor units с currency; суммы берутся из Go analytics.
Плановый платёж не создаёт Posting. Account и payment instrument различны;
последние цифры не являются глобальным уникальным ключом. Существующие UUID,
проводки, источники и tenant isolation неизменны. Кредитный баланс показывается
со знаком как баланс кредитного счёта, без самостоятельного расчёта долга.
Нельзя объединять разные валюты или показывать stale analytics как актуальные.

## API и OpenAPI

Account получает optional paymentInstruments (массив id/name/bank/last4).
CreateAccount получает optional card (name/bank/last4). Неполная карта,
не четыре ASCII-цифры, карта наличного счёта — 422. Старые клиенты и счета
без инструмента допустимы. Обновить OpenAPI и generated TypeScript.

## Данные, миграция и rollback

Аддитивная миграция payment_instruments с owner_id/RLS/составным FK на accounts,
GRANT ограниченной роли. Создание счёта и инструмента атомарно. Старые строки
не переписываются. Rollback приложения сохраняет новую таблицу; down migration
только вручную после сохранения её данных. Номер миграции требует согласования
при последующей интеграции незавершённого PR 7 — не перезаписывать его миграцию.

## Ошибки и негативные сценарии

Первоначальная загрузка, пустой набор, частичная ошибка каждого запроса,
повтор, отсутствие категорий; доступные секции работают независимо.
После неясного сетевого результата создания счёта автоматический повтор не
делается; пользователю предлагается проверить список. Confirmation операции
сохраняет введённые данные при ошибке. Не поддерживаемые сведения — неизвестны.
