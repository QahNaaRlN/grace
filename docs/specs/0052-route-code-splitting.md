## Проблема и пользовательский результат

`npm run build` (и значит `make test`) собирает весь клиент в один JS-чанк и
предупреждает, что он больше 500 кБ после минификации. На `main` `4785143`:
`index-*.js` — 900,79 кБ (gzip 263,67 кБ). Ветка `codex/credit-cards`
(SPEC-0051) добавляет к нему новые экраны. Каждый вход в Grace загружает код
всех страниц, включая графики `recharts`, импорт и ассистента, даже если
пользователь открыл только «Операции».

Результат: каждая страница из `pages/*` загружается своим чанком при первом
переходе на неё, основной чанк меньше 500 кБ, предупреждение в сборке
исчезает. Поведение, адреса и тексты не меняются.

SPEC-0048 (открытое решение 3) вынесла code splitting маршрутов в отдельную
спецификацию; это она.

## Scope

- В `web/src/app/router.tsx` все 13 срезов `pages/*` подключаются через
  свойство `lazy` маршрутов React Router (`RouteObject.lazy`) с динамическим
  `import()` публичного API среза (`@/pages/<slice>`), а не статическим
  импортом.
- `AuthBoundary` и `AppLayout` (`widgets/app-shell`) остаются в основном
  чанке: оболочка рисуется сразу, страница подгружается внутри неё.
- `/register`, `/forgot-password`, `/reset-password` используют один чанк
  `password-entry`, проп `view` сохраняется.
- Поведение при ошибке загрузки чанка — по открытому решению 2.
- Тест маршрутизатора проверяет, что ни один срез `pages/*` не импортируется в
  `app/router.tsx` статически.

## Non-goals

- Ручная настройка `build.rolldownOptions.output.codeSplitting` / `manualChunks`
  и повышение `chunkSizeWarningLimit`.
- Предзагрузка чанков по наведению на ссылку, prefetch.
- Разделение внутри страницы (отдельные диалоги, графики).
- Изменение кеширования в `web/nginx/default.conf` и в Caddy.
- Изменение структуры срезов FSD и их публичных API.

## Предметная модель и инварианты

- Набор URL и их вложенность в layout route не меняются (SPEC-0048 AC8,
  `router.test.tsx`).
- Проверка сессии `AuthBoundary` по-прежнему выполняется до показа защищённой
  страницы.
- `app` остаётся единственным слоем, который знает о маршрутах; `pages` не
  импортируют друг друга (правила Steiger не ослабляются).

## API и OpenAPI

Не меняются.

## Данные, миграция и rollback

Данные не затрагиваются. Rollback — revert коммита, возвращающий статические
импорты.

## UI

Видимых изменений нет. При первом переходе на страницу React Router ждёт
загрузки её чанка и до этого оставляет на экране текущую страницу (так же, как
при обычной навигации data router), поэтому новый индикатор и новые тексты не
нужны. При первом открытии приложения оболочка рисуется, когда загружен чанк
стартовой страницы.

## Ошибки и негативные сценарии

- **Устаревшая вкладка после деплоя.** Пользователь держит открытой вкладку
  прошлого выпуска и переходит на страницу, чанк которой ещё не загружал.
  Старый файл отдаёт 404, `import()` падает. Без обработки React Router
  показывает свой экран ошибки с английским текстом. Решение — открытый
  вопрос 2.
- **Нет сети** при первом переходе — тот же сценарий, что и выше.
- Повторная перезагрузка не должна зацикливаться, если чанк недоступен и после
  обновления страницы.

## Открытые решения

Все три приняты владельцем 2026-10-16 по рекомендациям: 1 — `RouteObject.lazy`;
2 — вариант (а); 3 — все страницы.

1. **`RouteObject.lazy` или `React.lazy` + `Suspense`.** Рекомендация —
   `lazy` маршрута: это штатный механизм data router (`createBrowserRouter`
   уже используется), он держит текущую страницу до загрузки следующей и не
   требует fallback-разметки и новых текстов. `React.lazy` потребовал бы
   `Suspense` с индикатором загрузки внутри оболочки — это новое видимое
   поведение.
2. **Обработка ошибки загрузки чанка.** Рекомендация — один раз перезагрузить
   страницу по целевому адресу (браузер получит новый `index.html` и новые
   чанки); защита от цикла — отметка в `sessionStorage`, снимаемая после
   успешной загрузки. Если чанк недоступен и после перезагрузки — показать
   экран ошибки маршрута. Варианты: (а) только перезагрузка, при повторе —
   стандартный экран React Router; (б) перезагрузка плюс свой `errorElement`
   на русском с кнопкой «Обновить» — это новый текст интерфейса, его
   формулировку утверждает владелец; (в) ничего не делать в этой спецификации.
   Рекомендация — (а).
3. **Все страницы или только тяжёлые** (`analytics`, `imports`, `assistant`,
   `payments`). Рекомендация — все: только тяжёлые не гарантируют запас под
   500 кБ при росте приложения, а единое правило проще проверять тестом.
