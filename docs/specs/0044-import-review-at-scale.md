## Проблема и пользовательский результат

История импортов — ряд кнопок «источник · на проверке/завершён» без даты,
файла и итогов. Строки черновика показываются сеткой крупных карточек по две
в ряд (до 100 за страницу); на 500 строк это 250 экранов прокрутки, а
нужное («не проверено», «есть вопросы») не выделено. Результат: история
отвечает «что, когда и с каким итогом загружено», а проверка 500 строк идёт
по очереди нерешённых, а не прокруткой.

## Scope

1. **История импортов** — таблица/список: источник, имя файла, тип
   (CSV/JSON), загружено (дата и время), период операций, строк всего и по
   статусам (не проверено / решено / подтверждено / исключено), последнее
   подтверждение (дата, время, создано операций), статус черновика.
2. **Сводка черновика** вверху: счётчики по статусам как фильтры-кнопки
   («Не проверено 37 · С вопросами 12 · Подтверждено 191 · …»), прогресс
   «проверено 412 из 500».
3. **Строки — компактная таблица**: чекбокс, лист·строка, дата, вид, сумма
   (`Money`), описание, статус (`StatusBadge`), число вопросов; 48px строка;
   на телефоне — двухуровневая строка. Подробности и решение — в боковой
   панели по нажатию (как сейчас форма «Проверка»), без ухода со списка.
4. **Масштаб:** серверная пагинация (размер 50/100), сортировка (строка,
   дата, сумма), поиск по описанию; «Выбрать все по фильтру (N)» для
   массового предпросмотра; режим «Следующая нерешённая» — после сохранения
   решения панель открывает следующую строку с вопросами.
5. Листы-свидетельства («Первичные документы») — отдельная вкладка, не
   смешиваются с операциями.

## Предметная модель и инварианты

- Счётчики по статусам, прогресс и «следующая нерешённая» считает Go.
- «Выбрать все по фильтру» передаёт фильтр, а не список id, с ревизией
  черновика; предпросмотр по-прежнему обязателен перед подтверждением.

## Ошибки и негативные сценарии

500 и 5 000 строк; фильтр без результатов; изменение черновика другим
окном (revision); массовый выбор > лимита предпросмотра — объяснение и
разбиение.
