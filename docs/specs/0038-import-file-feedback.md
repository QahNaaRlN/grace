## Проблема и пользовательский результат

На «Импорт» → «Новый черновик» после выбора CSV/JSON видно только нативное
имя файла; непонятно, готов ли файл, идёт ли сохранение и сохранён ли
черновик. Сообщения об успехе и ошибке появляются вверху страницы, далеко от
формы. Результат: человек видит три различимых состояния — «файл выбран»,
«сохраняем», «черновик сохранён» (или ошибку с повтором) — прямо в карточке
формы, не путая сохранение черновика с подтверждением финансовых операций.

## Scope

- Состояние выбранного файла в карточке «Новый черновик»: имя, размер
  (КБ/МБ, `ru-RU`), тип (CSV / снимок JSON), текст «Файл выбран — готов к
  сохранению», иконка; кнопка «Заменить файл» (повторный выбор) и «Убрать».
- Проверка до отправки: расширение `.csv`/`.json` и размер ≤ 16 MiB — ошибка
  в карточке словами, кнопка сохранения недоступна.
- Во время запроса: кнопка «Сохраняем…», поле файла недоступно, статус
  «Сохраняем черновик на сервере…».
- После ответа: `Notice tone="success"` «Черновик сохранён. Финансовые
  операции ещё не созданы.» в карточке; при ошибке — `Notice tone="danger"`
  с текстом сервера и кнопкой «Повторить» (тот же файл, новый
  Idempotency-Key только после изменения файла).
- Все сообщения формы — внутри карточки, `aria-live="polite"` для статуса,
  не только цветом (иконка + слово). Верх страницы остаётся для ошибок
  загрузки списка черновиков.
- Курсор: `pointer` у доступного поля и кнопки выбора файла (уже есть),
  `not-allowed` у недоступного — проверить и закрепить тестом.

## Предметная модель и инварианты

- «Выбран» ≠ «сохранён»: до ответа сервера файл не называется загруженным.
- Сохранение черновика не создаёт финансовых операций; текст это говорит.
- Повтор после ошибки отправляет те же байты; повторная запись защищена
  Idempotency-Key на сервере (существующее поведение).

## UI

Карточка «Новый черновик»: поле выбора (Field) → блок выбранного файла
(иконка FileText, имя с переносом, «CSV · 1,2 МБ», статус, «Заменить» /
«Убрать») → «Как подготовить файл» → название источника (для CSV) → кнопка
«Сохранить черновик» → Notice результата. 320px: блок файла в столбик.

## Ошибки и негативные сценарии

Файл 16 MiB + 1 байт; `.xlsx`; пустой файл; отмена диалога выбора (состояние
не меняется); выбор другого файла после ошибки (ошибка снимается); ошибка
сети; `invalid_csv`; двойной клик «Сохранить» (один запрос); очень длинное
имя файла; screen reader объявляет «Файл выбран…», «Сохраняем…», «Черновик
сохранён».

## Критерии приёмки

- [ ] AC1: после выбора допустимого файла в карточке видно имя, размер, тип и
  «Файл выбран — готов к сохранению»; есть «Заменить файл» и «Убрать».
- [ ] AC2: недопустимый тип или размер > 16 MiB — ошибка словами в карточке,
  сохранение недоступно, запрос не отправляется.
- [ ] AC3: во время сохранения — «Сохраняем…», поле и кнопка недоступны,
  один запрос при двойном клике.
- [ ] AC4: успех — Notice «Черновик сохранён…» в карточке; ошибка — Notice с
  текстом и «Повторить»; сообщения формы не появляются вверху страницы.
- [ ] AC5: статусы объявляются через `aria-live="polite"`/`role`, у каждого
  иконка и слово.
- [ ] AC6: `cursor: pointer` у доступного выбора файла, `not-allowed` у
  недоступного (тест по классам).
