# Decision 0003: Feature-Sliced Design для Web

- Статус: accepted
- Дата: 2026-10-15
- Владелец решения: owner
- Основание: [SPEC-0048](../specs/0048-frontend-fsd-architecture.md)

## Решение

`web/src` организуется по Feature-Sliced Design 2.1. Соблюдение правил
проверяется автоматически в `make test`:

- Steiger с `@feature-sliced/steiger-plugin` (`npm run lint:fsd`, обёртка
  `scripts/lint-fsd.mjs`) проверяет
  направление импортов, public API срезов и сегменты;
- локальные ESLint-правила `web/eslint-rules/grace.js` и `no-restricted-imports`
  запрещают литералы ключей React Query вне `entities/*/api`, прямую инвалидацию
  вне хуков мутаций, литерал часового пояса вне `shared/config` и ручную
  передачу CSRF-токена;
- Prettier (`npm run format:check`): пробелы, 2 отступа, без `;`, одинарные
  кавычки, ширина 100.

Правило Steiger `fsd/insignificant-slice` выключено: в Grace фича — это
пользовательское действие, и срез, которым пользуется одна страница, допустим.

Нарушения, существовавшие до перехода, перечислены в `web/steiger.baseline.json`
и `web/eslint.baseline.js`. Новые записи туда не добавляются; каждая фаза
SPEC-0048 только сокращает списки, последняя удаляет их.

Baseline Steiger сверяется по каждой диагностике (правило, файл, сообщение)
обёрткой `web/scripts/lint-fsd.mjs`, а не через `files`/`off` в конфиге Steiger.
Steiger исключает «выключенные» файлы из модели проекта для правила, поэтому
новые импорты в такие файлы тоже перестали бы проверяться. Обёртка падает на
новых нарушениях и на исправленных, но не удалённых из baseline
(`npm run lint:fsd -- --prune`).

Известное ограничение: Steiger не распознаёт срезы без сегментов
(`pages/login`, `pages/imports` и др.), поэтому импорты между такими страницами
он не видит. Это закрывается фазами 3–4, где страницы получают сегменты.

## Причины

- до решения слои FSD существовали только как каталоги: `entities` и `widgets`
  были пусты, страницы импортировали страницы, фичи — фичи;
- одна страница обслуживала восемь маршрутов, а серверное состояние, даты и
  CSRF дублировались в компонентах;
- без автоматической проверки структура снова расходится с правилами.

## Следствия

- новый код сразу размещается по слоям и не попадает в baseline;
- массовое форматирование выполнено одним коммитом, указанным в
  `.git-blame-ignore-revs`;
- замена библиотек состояния, форм или UI kit этим решением не вводится.
