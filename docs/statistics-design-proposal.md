# Статистика Grace: предложение

Статус: proposal, не accepted implementation scope. 2026-10-09.
Владелец попросил добавить графики/диаграммы и обсудить направление.

## Первый этап

| Вопрос | Представление | Детали |
| --- | --- | --- |
| Куда уходят деньги? | Горизонтальные столбцы расходов по категориям | Сумма, доля, без категории отдельной строкой; открыть операции |
| Как меняются траты? | Столбцы по неделям/месяцам | Динамика расходов; сравнение только сопоставимых периодов |
| Доходов хватает на расходы? | Парные столбцы доходов и расходов по месяцам | Переводы между своими счетами не считаются доходами/расходами |

На обзоре одна компактная карточка динамики + сумма и полнота данных.
На отдельной странице статистики: период, валюта, три графика, таблицы.
Петрольный — основной ряд; вспомогательные ряды используют общие chart tokens.

## Затем

Доступность денег до выбранной даты: график остатка по известным платежам.
Фактическая история — сплошная линия, прогноз — пунктир. Прогноз строится Go
из сверённых остатков и обязательств, с явной границей покрытия/неизвестного.
Если исходный остаток неизвестен, значение не заменяется нулём.

## Правила

- Расчёты и агрегация на backend, деньги в minor units, отдельные валюты.
- День без данных не равен подтверждённому нулю расходов. Для полного периода
  ноль допустим при отсутствии событий; неполнота импорта обозначается отдельно.
- Столбцы начинаются с нуля. Нет 3D, сглаживания, выдуманных трендов и рейтинга
  финансового здоровья без принятой методики.
- Подписи/значения и таблица доступны без hover; tap и клавиатура.
- У каждого графика период, единицы, источники и краткий текстовый итог.
- Сравнение текущего неполного месяца только с теми же днями предыдущего
  или явно обозначенными полными месяцами без вводящего в заблуждение процента.

## Зависимости

Проверено: текущий Analytics в HomePage.tsx показывает period-summary и
cash-position; API содержит эти агрегаты. Наличие готовых временных рядов
и категорийных агрегатов не подтверждено. Перед реализацией — принятая spec,
контракт API, агрегация/coverage на Go, затем отображение в web.
Графики не внедрены этой проработкой.
